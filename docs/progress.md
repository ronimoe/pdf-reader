## M0: Skeleton (branch `m0-skeleton`)

**Landed**
- `project.yml` for XcodeGen, defining the `Lectern` app and the `LecternTests` unit-test bundle hosted in the app.
- The `Packages/LecternKit` local package, with five targets: ReaderCore, PDFSave, Persistence, ReaderKit and ReaderUI. ReaderKit and ReaderUI default to `MainActor`.
- **App.** A `ReaderDocument` subclass of `NSDocument` with autosave, drafts and Versions turned off (A1). It keeps the original bytes in memory and builds a `PDFDocument` from them.
- **Window.** `ReaderWindowController` hosts a `ReaderPDFView`, and the menu bar is built in code.
- **Sandbox entitlements:** read-write access to files the user chooses, app-scoped bookmarks, and outgoing network connections.
- **Document type.** The app registers for PDF with rank `Alternate`, so it never takes over as the default PDF app.
- **ReaderCore.** `ReadingAnchor`, with page clamping for when a file changes (A2).
- `scripts/test.sh`, a one-command headless test run.

**Verified**
- `scripts/test.sh` passes all suites: 5 package tests through `swift test`, and 3 app-hosted tests through `xcodebuild test`.
- The app-hosted tests run with ad-hoc signing and the sandbox on, and no privacy prompt appears.

**Doc changes**
- architecture.md §8: the Xcode project is now generated by XcodeGen. See the amendment there.

**Review fixes** (code-reviewer on PR #1)

**Verified**
- 11 writer runs, each checked against the pass criteria:
  - the original bytes are an exact prefix of the output,
  - `qpdf --check` passes,
  - PDFKit shows the right annotations,
  - form values are byte-identical,
  - the signature is reported intact,
  - MuPDF, Poppler, pdf.js and PDFKit all draw the highlights.
- Encrypted files are refused with a typed error.
- Mutation checks: deliberately corrupted outputs are caught.
